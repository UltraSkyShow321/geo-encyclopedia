## 2. 整体架构

```
手机 / 电脑浏览器 (PWA, 可离线)
        │ HTTPS
        ├──────────────┬─────────────────────────────┐
        ▼              ▼                             │
 绿联远程访问     Cloudflare 边缘网络                 │
 (境内中转,快)    (CDN + TLS, 海外友好)              │
        │              │                             │
        └──────┬───────┘                             │
               ▼                                     │
┌─────────── 绿联 NAS (Docker Compose) ───────────┐  │
│  app 容器      : Node.js API + Vue 静态资源     │  │
│  cloudflared   : Cloudflare Tunnel 隧道出口(备) │  │
│  data 卷       : SQLite 数据库 + 图片等持久化   │  │
└────────────────────────────────────────────────┘  │
  app 只监听 127.0.0.1:3000，两条链路都指向它        │
  随时切换，互不依赖                                 │
```

要点：
- NAS 上**只需 Docker**，共 2 个容器（app、cloudflared），内存占用预计 < 512MB。
- app 容器**只监听本机回环端口**，不对公网开放；外网访问一律走穿透链路。
- 所有数据存在 `./data` 卷和 `./content` 目录，可随时打包备份/迁移。

## 4. 内容体系

### 4.1 内容分类
1. **国家/地区档案**（目标约 195 国）：首都、人口、面积、官方语言、货币、政体、时区、国旗、地理概况、历史沿革、经济、文化等；统计数字来自 Wikidata，叙述文字为 AI 草稿 + 人工校对，英文名词以括号附注。
2. **自然地理专题**（首批约 20–30 个）：世界十大山脉/河流/湖泊/沙漠/岛屿、气候带、板块构造与地震火山、洋流、极地等。
3. **人文地理专题**：世界遗产、主要城市、人口分布、宗教与语言分布、经济区域等。
4. **互动地图**：世界地图按大洲/人口/面积着色，点击国家跳转档案页；专题页附标注图（如河流、山脉）。
5. **数据图表**：国家详情页内统计（人口趋势、GDP 对比等）+ 全局排行页。

### 4.2 内容生产流程（两者结合）
```
步骤1 [脚本] Wikidata SPARQL 批量拉取各国结构化字段
        → 生成 content/countries/{slug}.md（frontmatter 存数据，正文留骨架）
步骤2 [脚本] 调用 LLM（DeepSeek/OpenAI 兼容接口）批量生成概况与专题草稿
        → 填入正文，含英文名词附注
步骤3 [人工] 你在 Markdown 文件上逐篇校对修改（文件即内容，便于版本管理与备份）
步骤4 [自动] 应用启动/变更时导入 SQLite，重建搜索索引与统计缓存
```

### 4.3 内容存放
```
content/
├── countries/  ├── china.md, japan.md, ...
├── topics/     ├── mountains.md, rivers.md, ...
└── metadata/   ├── continents.json, cities.json ...
```

## 6. 部署方案（NAS）

### 6.1 docker-compose 概览
```yaml
services:
  app:
    build: .            # Node.js 应用 + Vue 构建产物
    ports: ["127.0.0.1:3000:3000"]   # 仅本机回环，不对公网开放
    volumes:
      - ./data:/app/data
    restart: always
  cloudflared:
    image: cloudflare/cloudflared
    command: tunnel --no-autoupdate run --token <TUNNEL_TOKEN>
    restart: always
```

### 6.2 外网访问链路（双穿透方案）
> 背景：Cloudflare 免费版在国内无节点，高峰期延迟高、可能丢包；绿联远程访问走境内中转，国内速度快但域名固定、依赖绿联服务。两者互补，**默认走绿联，CF 备用**。

**主链路 — 绿联远程访问（零部署）**
1. NAS 上启动 app 容器（监听 `127.0.0.1:3000`，经 Docker 端口映射对外）
2. UGOS Pro「远程访问」设置中为容器端口添加映射，生成公网 HTTPS 地址（绿联分配的 `*.ugreenxxx.link` 类域名）
3. 浏览器收藏该地址即可多端访问；URL 固定，适合日常使用
4. 限制：不能绑定自有域名；稳定性依赖绿联中转服务

**备链路 — Cloudflare Tunnel（需要域名）**
1. app 只监听回环端口，云原生的 cloudflared 容器以出站连接注册到 CF，NAS 零端口暴露
2. 域名落地后：Cloudflare 面板建 Tunnel → cloudflared 容器带 token 运行 → 配置 `www.你的域名 → http://app:3000`
3. 可加 Access 策略（登录 Cloudflare 账号才能访问）双重保护；海外访问走 CF 更快
4. 域名落地前可用 quick tunnel（`*.trycloudflare.com` 临时地址）验证功能

**切换规则**：两条链路指向同一个 `127.0.0.1:3000`，互不依赖。绿联地址卡顿时用 CF 域名，反之亦然；任一条故障不影响另一条。

### 6.3 备份策略
- SQLite + content 目录每日/每周打包到 NAS 其他目录或网盘（脚本或 NAS 定时任务）
- 内容本身是 Markdown 文本，天然可版本管理

### 8.1 域名方案（无域名情况下的路线）
1. **验证期**：Cloudflare quick tunnel 提供 `*.trycloudflare.com` 临时域名，隧道随容器重启会变化，仅用于本地/短期测试，不用于正式分享。
2. **正式域名**（二选一，成本低）：
   - 购买便宜域名（.xyz/.top 等首年约 ¥10–30，或 .com 约 ¥70/年），注册后**免费**接入 Cloudflare 免费版；
   - 申请免费域名 eu.org（可自定义 NS 指向 Cloudflare，审核约 1–4 周，零成本）。
3. 域名落地后：Cloudflare 面板建 Tunnel → NAS 上 cloudflared 容器带 token 运行 → 配置 `www.你的域名.com → http://app:3000`，可选加 Access 登录保护。
